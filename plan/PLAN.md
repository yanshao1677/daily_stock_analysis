# 初筛模式改造方案

## Summary
新增一个独立的“初筛模式”，用于批量股票池的轻量筛选，不改现有完整分析流程。初筛结果按三档输出：`淘汰`、`观察`、`深入分析`；规则引擎先做主判断，LLM 只对非淘汰标的做简短复核和解释，不再生成完整报告、精确点位或写入正式分析历史。

## Key Changes
### 1. 后端新增独立初筛链路
- 新增独立 screening pipeline，复用现有数据获取、趋势分析、基本面聚合、新闻检索能力，但跳过完整 `GeminiAnalyzer.analyze()` 报告生成。
- 初筛主评分以现有 `StockTrendAnalyzer.signal_score` 为核心，再叠加三类调整项：
  - 风险扣分：近窗新闻命中减持、处罚、业绩爆雷、监管风险等硬风险时直接降档或淘汰。
  - 结构加减分：筹码结构、实时量比/换手率、基本面缺失程度只做轻量修正，不引入新的复杂公式。
  - 数据质量扣分：历史数据不足、实时数据缺失、新闻时间不可判定时降低可信度，但不默认淘汰。
- 初筛分层固定为：
  - `淘汰`：命中硬性否决，或最终分 `< 45`
  - `观察`：最终分 `45-64`
  - `深入分析`：最终分 `>= 65`，且未命中硬性否决
- 硬性否决固定为：
  - 历史行情不足以完成趋势分析
  - 趋势为 `BEAR` / `STRONG_BEAR`
  - `bias_ma5 > 7%` 的明显追高状态
  - `HEAVY_VOLUME_DOWN`
  - 近窗新闻命中重大明确利空
- 输出固定包含：`rule_score`、`screen_tier`、`reasons`、`blockers`、`data_quality`、`needs_deep_analysis`。

### 2. LLM 改为“候选复核器”
- LLM 不参与淘汰票；只处理 `观察` 和 `深入分析` 标的。
- LLM 输入使用新的短 prompt，只允许做三件事：
  - 用一句话总结“为什么进入该档”
  - 提示 1-2 个最关键风险或确认条件
  - 对规则分层做轻量复核，但不能越过硬性否决
- LLM 输出固定为短字段，不生成完整 dashboard，不输出买点/止损/目标价。
- 默认只对规则分最高的前 `20` 只非淘汰标的跑 LLM，避免批量股票池成本失控；其余仅返回规则结果。

### 3. API 与任务形态
- 不改现有 `/api/v1/analysis/analyze` 语义。
- 新增独立接口 `POST /api/v1/analysis/screen`。
- 新请求模型与 `AnalyzeRequest` 保持相近，但只支持批量语义，核心字段：
  - `stock_codes`
  - `async_mode`
  - `force_refresh`
  - `notify` 默认 `false`
- 新响应模型返回：
  - 批次摘要：总数、淘汰数、观察数、深入分析数、LLM复核数
  - 每只股票的 screen item 列表
  - shortlist：按最终分排序的 `深入分析` + `观察` 结果
- 异步模式复用现有任务队列/SSE 机制，但任务类型区分为 `screen`，避免和完整分析任务混淆。
- 初筛结果不写入 `analysis_history`，不进入现有回测链路；如需保留，只做单独 screening snapshot，和正式分析记录隔离。

### 4. Web 侧最小接入
- 在现有股票池/批量分析入口新增“初筛”动作，不替换当前“完整分析”入口。
- 初筛结果页面按三组展示：`深入分析`、`观察`、`淘汰`，每项展示规则分、短理由、关键阻塞项。
- 对 `深入分析` 组提供“继续完整分析”动作，直接把 shortlist 送入现有完整分析接口。
- 首页/历史页不混入初筛记录，避免把筛选结果误当成正式分析报告。

### 5. 文档与配置
- 新增 screening 配置项并写入 `.env.example`：
  - `SCREENING_ENABLED`
  - `SCREENING_LLM_TOP_N`
  - `SCREENING_NEWS_WINDOW_DAYS`（默认复用现有新闻窗口）
- 更新 `README.md` / `docs/full-guide.md` / `docs/CHANGELOG.md`，明确：
  - 初筛只做候选分层，不给交易点位
  - LLM 在初筛中只是复核解释器
  - 初筛结果不会替代正式分析与回测

## Test Plan
- 后端规则分层测试：
  - 明确空头/放量下跌/重大利空样本进入 `淘汰`
  - 中性结构进入 `观察`
  - 多头、不过热、无重大风险样本进入 `深入分析`
- LLM 约束测试：
  - 淘汰票不触发 LLM
  - 非淘汰票只返回短摘要字段，不返回完整 dashboard
  - LLM 不得把命中硬否决的票提到更高档
- API 契约测试：
  - `/analysis/screen` 同步/异步、批量上限、输入校验、SSE 任务类型
  - 初筛结果不落入 `analysis_history`
- 前端交互测试：
  - 股票池触发初筛
  - 三档结果展示与排序
  - shortlist 转完整分析链路
- 文档/配置测试：
  - 新环境变量可解析
  - docs 中命令、接口名、字段名与实现一致

## Assumptions
- 默认采用“中性偏保守”筛选风格。
- 默认产品定位是“规则初筛 + LLM 复核 + 人工/完整分析二次决策”，不是自动交易。
- 默认不复用 `report_type` 承载初筛语义，避免污染现有报告类型契约。
- 默认初筛结果与正式分析历史隔离，不参与现有回测指标。
